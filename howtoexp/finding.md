# HunyuanVideo：K96 Core 后如何选择高性价比 K16

## 结论先行

现有数据已经足以回答机制问题：**K96 Core 确实会漏掉少量但恢复收益很高的 K16；难点不是证明它们存在，而是当前均值池化 proxy 无法在线把它们排到前面。**

对 Residual 而言，每个候选都是同样大小的 `Q16×K16` tile，计算成本基本相同，因此单块的恢复性价比可以直接定义为：

\[
\Delta E(q,k)=E_{\mathrm{Core}}(q)-E_{\mathrm{Core}+K16_k}(q).
\]

每个 Q16 在 Core 补集中使 \(\Delta E\) 最大的 K16，就是该 Q16 的真实最佳遗漏 tile。按这个目标看，当前最明确的判断是：

1. **不能继续把当前 proxy 总质量当作主要 Residual 判据。** 对最值得挽救的严重遗漏，它的排序几乎失效，而且经常错误判断“Core 已经够了”，从而不给 Residual 任何预算。
2. **Macro 总分 \(M\) 不是高性价比小块选择的充分条件。** 它在真实 dense attention 上能定位高价值区域，但当前 proxy 估不准；即使估准，选择一个 K96 也要付出 6 个 K16 的成本，不等价于找到性价比最高的一个 K16。
3. **峰值 \(A\) 比 \(M\) 略好，但当前 proxy 下仍远远不够。** 它可以保留为候选特征，不能单独作为方法。
4. **Layer/Head 规律很强，固定 K anchor 规律不强。** Layer/Head 适合做预算门控；具体 K16 仍必须根据当前 Q、当前视频在线发现。
5. **遗漏 tile 具有明显时间邻近性，但不是普通的空间/线性局部邻域。** 时间带可以用于缩小候选集，不能用局部窗口硬替代全局候选。

因此，目前最合理的方法方向不是“再换一个静态 Top-p 阈值”，而是：**先用 Layer/Head/step 先验分配预算，再在时间邻近但空间仍可全局的候选中，学习或构造一个比均值池化 proxy 更接近真实 tile attention mass 的在线 score。** 在新 score 被证明有效前，最稳妥的基线仍是：在 Core 补集中按现有 fine proxy 分数选 Top-k K16；但必须明确，这只是可实现的基线，不是现有数据支持的高召回方案。

## 数据范围与评价对象

正式统计来自：

`/cnic/work/liutt/mywork/attention_time/res/Hunyuan_K16_DeltaE_3Videos_K96Core_20260908`

- 3 个视频提示词；diffusion step 为 12、24、36；layer 为 9、12、15；覆盖 24 个 heads。
- 共 27 个 QKV snapshot。
- 每个视频采样 1,152 个 Q16，其中每个 snapshot 含 64 个高误差 Q16 和 64 个低误差 control。
- 三个视频合计 3,456 个 Q16、1,202,688 个 Core 遗漏 K96、7,216,128 次独立 K16 add-back。
- 其中高误差样本 1,728 个；再取“最佳单 K16 恢复收益”最高的 10%，得到 173 个严重遗漏。阈值为 \(\Delta E\ge 0.243955\)。

下文把这 173 个严重遗漏作为方法设计的主要对象，因为 Residual 的价值首先在于挽救这些大误差，而不是提高大量本来误差很小的样本的平均命中率。

正式的 ratio=0.20 三视频实验现已完成；ratio=0.25 作为较高 Core 覆盖率的对照基线保留。两组数据均为 27 个快照、3,456 个 Q16，且所有快照都通过 ratio、Core-only 和 route metadata 校验。下面先给出 ratio=0.25 的基线，再给出 ratio=0.20 的复合验证。

另外，每个 K16 都是从同一个 Core 状态单独 add-back。多个 K16 同时加入时存在 softmax 相互作用，所以各 tile 的 \(\Delta E\) **不能相加**；现有结果衡量的是“最佳单块”和“候选召回”，不是最优多块组合。

## 0.20 复合验证：结论是否随 Core 比例改变？

ratio=0.20 的正式结果位于：

`/cnic/work/liutt/mywork/attention_time/res/Hunyuan_K16_DeltaE_3Videos_K96Core_Ratio020_20260908`

三视频的 K16 detail 行数均为 2,571,264，总计 7,713,792 次独立 K16 add-back。与 ratio=0.25 的对照如下；严重遗漏仍定义为高误差样本中最佳单 K16 收益最高的 10%，每组都是 173 个 Q16。

|指标|Core ratio=0.25|Core ratio=0.20|解释|
|---|---:|---:|---|
|严重遗漏阈值|0.2440|0.2820|Core 更少时，漏选块的潜在收益更大|
|严重遗漏最佳 \(\Delta E\) 均值|0.3469|0.3966|问题更值得挽救|
|当前 proxy K16 Top1/Top5/Top20|2.3/5.8/9.2%|1.2/5.2/12.1%|仍然很弱，未形成可用排序|
|当前 proxy Macro \(M\) Top1/Top5/Top20|1.2/3.5/11.0%|1.7/4.0/16.2%|略有波动，不能依赖|
|当前 proxy Macro \(A\) Top1/Top5/Top20|2.3/6.4/13.9%|1.2/6.9/17.9%|略优但仍不足|
|真实 dense K16 mass Top1/Top5/Top20|66.5/83.2/89.0%|72.3/90.8/95.4%|oracle 规律稳定且更强|

这组对照验证了两点：

1. **Core ratio 降到 0.20 并没有修复 proxy 排序问题。** Top20 仍只有 12.1%（K16）、16.2%（(M)）和 17.9%（(A)）。
2. **dense mass 的可预测性不是偶然。** ratio=0.20 下真实 dense K16 Top5 已达到 90.8%，比 ratio=0.25 的 83.2% 更强；这进一步说明真正需要补的是在线 dense-mass 近似，而不是固定位置规则。

### 0.20 下的 Layer/Head 和位置复验

ratio=0.20 的 173 个严重遗漏中，171 个（98.8%）在 Layer 12；Head 8/18/5 分别为 133、20、13 个，合计 166/173（96.0%）。因此 Layer/Head 预算门控规律不仅没有消失，反而更集中。

但最佳 K16 位置发生明显变化：最高频位置为 K16=1772（14 个）、1053（12 个）、168 和 2224（各 9 个）。这与 ratio=0.25 的 1772（24 个）、2180（7 个）、168/2328（各 6 个）不同，直接说明这些位置频率受内容和 Core 覆盖率影响，不能当固定 anchor。

留一视频位置先验在 ratio=0.20 的严重遗漏上总体 Top1/Top5/Top20 只有 **1.7%/3.5%/16.8%**；三个留出视频分别为 **4.2/8.5/11.3%**、**0/0/27.3%**、**0/0/0%**。因此复合验证仍然排除“跨视频固定 K 位置表”。

### 0.20 下当前 Residual 的成本—召回复验

用 ratio=0.20 的原始 proxy 质量模拟 `topk_topp + total Top-p Residual`：

|严重遗漏范围|`p_total`|最佳 K16 被选中|Residual 为空|Residual K16 数（均值/中位数）|
|---|---:|---:|---:|---:|
|173 个严重遗漏|0.90|31.8%|68.2%|72.0 / 0|
|173 个严重遗漏|0.95|59.5%|40.5%|225.9 / 55|

与 ratio=0.25 的 3.5%/74.6%（\(p=0.90\)）和 16.2%/50.3%（\(p=0.95\)）相比，ratio=0.20 的召回明显提高，但原因首先是 Core 少了、Residual 被迫留下更多概率质量，而不是 proxy 变准了。代价也同步上升：\(p=0.90\) 时严重遗漏的平均 Residual 数从 35.9 增至 72.0，\(p=0.95\) 时从 158.1 增至 225.9；两种 ratio 的中位数仍分别为 0，说明预算依旧集中在错误的 query 上。

所以 ratio=0.20 复验后的结论不是“把 Core 降低就解决了漏选”，而是：**较低 Core 给 Residual 更多挽救空间，但仍需要更好的 query 风险门控和 tile score；单纯提高 total Top-p 仍然是高成本补救。**

## 0.16 复合验证：进一步降低 Core 后的结果

ratio=0.16 的正式结果位于：

`/cnic/work/liutt/mywork/attention_time/res/Hunyuan_K16_DeltaE_3Videos_K96Core_Ratio016_20260908`

三视频均已完整完成 27 个 snapshot 和独立 add-back；每个视频 2,695,680 条 K16 detail，总计 8,087,040 条。173 个严重遗漏的关键结果如下：

|指标|Core ratio=0.20|Core ratio=0.16|解释|
|---|---:|---:|---|
|严重遗漏阈值|0.2820|0.3449|Core 更少时单块遗漏收益继续增大|
|严重遗漏最佳 \(\Delta E\) 均值|0.3966|0.4754|Residual 目标更有价值|
|当前 proxy K16 Top1/Top5/Top20|1.2/5.2/12.1%|2.9/5.2/9.8%|仍不能稳定发现真实最佳块|
|当前 proxy Macro \(M\) Top1/Top5/Top20|1.7/4.0/16.2%|1.7/3.5/11.6%|没有稳定改善|
|当前 proxy Macro \(A\) Top1/Top5/Top20|1.2/6.9/17.9%|2.9/6.4/16.8%|略好于 \(M\)，仍不足|
|真实 dense K16 mass Top1/Top5/Top20|72.3/90.8/95.4%|76.3/97.7/99.4%|oracle 规律进一步增强|

### 0.16 下的结构规律

- 173 个严重遗漏 **全部发生在 Layer 12**。
- Head 8 单独占 151/173（87.3%）；Head 8/5/18 合计 167/173（96.5%）。
- Step 12、24、36 分别为 83、62、28 个；虽然前期仍较多，但 Step 36 的占比已上升到 16.2%。
- 高频最佳 K16 变为 1053（10 个）、215/1772（各 9 个）、2202（8 个），与 ratio=0.20 和 0.25 的高频位置都不相同。

这组结果把 Layer/Head 门控规律验证得更强，同时把固定 K anchor 排除得更彻底：**Core ratio 改变后，真实最佳位置会重排；稳定的是风险 head，不是 K 坐标。**

留一视频的 `(layer, head, K位置)` 先验在 ratio=0.16 严重遗漏上的总体 Top1/Top5/Top20 仅为 **1.2%/4.6%/12.7%**；三个留出视频分别为 **2.5/10.1/15.2%**、**0/0/11.5%**、**0/0/0%**，跨视频泛化仍然失败。

### 0.16 下 Residual 的成本—召回

用 ratio=0.16 的原始 proxy 质量模拟 `topk_topp + total Top-p Residual`：

|严重遗漏范围|`p_total`|最佳 K16 被选中|Residual 为空|Residual K16 数（均值/中位数）|
|---|---:|---:|---:|---:|
|173 个严重遗漏|0.90|39.9%|60.1%|97.7 / 0|
|173 个严重遗漏|0.95|70.5%|29.5%|273.8 / 125|

和 ratio=0.20 的 31.8%/68.2%（\(p=0.90\)）相比，ratio=0.16 的召回提高，但主要是因为 Core 更少、Residual 被迫选择更多 tile；平均 Residual 数从 72.0 增至 97.7。即使在 ratio=0.16、\(p=0.95\) 时达到 70.5% 召回，平均也要选择 273.8 个 K16，仍不是高性价比的在线发现方法。

因此三个比例的复合结论是一致的：降低 Core 能增加“可挽救”的误差和 Residual 召回空间，但不会修复 mean-pooled proxy 的排序盲区。应优先改进高风险 query 的 tile score；Core ratio 只是质量—成本旋钮，不是遗漏识别器。

## 1. 每个 Q16 的真实最佳遗漏 K16 能否找出？

可以。现有逐 K16 add-back 数据已经穷举了采样 Q16 的所有 Core 补集，因而可以直接取最大 \(\Delta E\) 作为 ground truth。

|样本集合|Q16 数|最佳单 K16 的平均 \(\Delta E\)|中位数|P90|最大值|
|---|---:|---:|---:|---:|---:|
|全部样本|3,456|0.0506|0.0120|0.1518|0.6681|
|高误差样本|1,728|0.0957|0.0578|0.2440|0.6681|
|严重遗漏|173|0.3469|0.3152|0.4941|0.6681|
|低误差 control|1,728|0.00546|0.00377|—|0.0830|

这说明单个遗漏 K16 的确可能恢复很大一部分误差，而且收益呈强长尾。Residual 的目标应当是识别这 173 类事件，而不是让所有 Q16 平均获得相同数量的小块。

## 2. 在线信号能否命中真实最佳 K16？

以下候选召回率均针对 173 个严重遗漏。Top-k 的含义是：按相应信号排序后，真实最佳 K16 是否落入前 k 个候选。

|候选规则|Top1|Top5|Top20|直接结论|
|---|---:|---:|---:|---|
|当前 K16 mean-pooled proxy|2.3%|5.8%|9.2%|基本无法识别严重遗漏|
|当前 proxy Macro \(M=\sum s\)|1.2%|3.5%|11.0%|Top1 比直接 K16 proxy 更差|
|当前 proxy Macro \(A=\max s\)|2.3%|6.4%|13.9%|略优于 \(M\)，仍不可用作单一标准|
|真实 dense K16 attention mass（oracle）|66.5%|83.2%|89.0%|真实质量与恢复收益强相关|
|真实 dense Macro \(M\)（oracle）|67.6%|87.3%|95.4%|质量总量的概念有效，问题在估计值|
|真实 dense Macro \(A\)（oracle）|67.1%|84.4%|92.5%|峰值概念也有效，但当前 proxy 没捕获到|

这里最重要的不是 “\(M\) 还是 \(A\) 谁高几个百分点”，而是 proxy 与 dense oracle 之间约一个数量级的差距：

- 当前 proxy K16 的 Top20 只有 9.2%，而真实 dense mass 的 Top20 是 89.0%。
- 当前 proxy 选出的 Top1，在严重遗漏上恢复收益相对 oracle-best 的平均比例只有约 5.7%，中位数只有约 0.05%。
- 因此，**真正缺失的是可靠的在线质量估计，而不是把同一份 proxy 换一种聚合方式。**

关于 \(M\) 的准确解释是：真实的 attention mass 大确实有意义，但“当前 mean-pooled proxy 算出的 \(M\) 大”意义很弱。并且对于固定 K16 成本的 Residual，应该优先预测单 tile 的 \(\Delta E\)，不能仅因一个 K96 的总质量大就一次支付 6 个 K16 的成本。

## 3. 固定 anchor、局部邻域，还是随内容变化？

### 3.1 Layer/Head：强集中，可用于预算门控

在 173 个严重遗漏中：

- 168 个（97.1%）发生在 Layer 12。
- Layer 12 Head 8 有 110 个（63.6%）。
- Layer 12 Head 18 有 35 个（20.2%）。
- Layer 12 Head 5 有 16 个（9.2%）。
- 上述三个 head 合计覆盖 161/173（93.1%）的严重遗漏。

按 step 看，Step 12、24、36 分别有 80、71、22 个严重遗漏，即 46.2%、41.0%、12.7%。前中期更值得投入 residual 预算，但 Step 36 不能完全关闭。

这给出了很直接的工程策略：**Residual 预算不应在所有层和 head 上均匀分配，应优先给 Layer 12 的 Head 8/18/5，并适当偏向 Step 12/24。** 但这只能判断“哪里更容易发生高收益遗漏”，不能判断某个 Q16 具体应该补哪个 K16。

还要注意，采样本身刻意选取了每个 snapshot 的高误差 Q16，因此这些比例表示“高误差事件由哪些 layer/head 主导”，不是全部 Q16 的自然发生率。

### 3.2 固定 K16 anchor：跨视频不稳定，不应作为主方法

严重遗漏中出现最多的全局位置是 K16=1772，占 24/173（13.9%），其余单个位置均不超过 4.1%。更关键的是：

- 三个视频各自 Top10 高频 K16 集合的交集为空。
- K16=1772 的集中主要由其中一个视频驱动，不是三个视频共有的 anchor。
- 用另外两个视频学习 `(layer, head, K位置)` 的平均 \(\Delta E\)，再到留出视频中排序，严重遗漏的总体 Top1/Top5/Top20 召回仅为 0.6%/0.6%/18.5%。
- 该 Top20 的 18.5% 也不稳定：三个留出视频分别为 7.0%、39.2%、0%。

因此，固定 anchor 或全局 K 位置表最多只能作为很弱的先验，不能成为 Residual 的选择主体。真实最佳 K16 明显随视频内容变化。

### 3.3 K96 内部位置和 Q128 内部位置：没有足够强的固定偏置

严重遗漏的最佳 K16 在一个 K96 内六个子块位置 `0..5` 上的计数为：

`35, 16, 42, 16, 27, 37`

Q16 在一个 Q128 内八个 offset `0..7` 上的计数为：

`28, 22, 14, 24, 17, 19, 21, 28`

虽不是完全均匀，但没有强到足以固定选某个子块；而且分视频分布会变化。不能通过“每个漏选 K96 固定补第 0/2/5 个 K16”解决问题。

### 3.4 局部性：时间近、空间不一定近

如果直接按 Hilbert 后的一维 K16 index 判断邻近，严重遗漏的真实最佳 K16：

- 落在 Q16 的 ±16 范围内：0%。
- ±32：1.7%。
- ±64：5.2%。
- ±128：8.7%。

所以普通的一维局部窗口基本无效。映射回视频三维坐标后，规律更清楚：

- 归一化时间距离的中位数约 0.031，明显小于全部遗漏候选的 0.313；说明重要 K16 往往在相同或相邻时间片。
- 但按完整三维最近邻排序，Top1/Top5/Top20 召回只有 0%/1.7%/9.2%。
- 单看空间最近邻更差，Top20 只有 0.6%。

因此不能把方法概括成“补 Q 附近的 K”。更准确的规律是：**时间上局部，空间上可能非局部。** 时间距离适合作为候选 score 的一个特征或软先验，不适合作为排除远端候选的硬窗口。

## 4. 当前 Residual 具体漏在哪里？

针对该批 `topk_topp`、Core ratio=0.25 的记录，用保存的原始 proxy 质量模拟当前 total Top-p Residual：

|范围|`p_total`|真实最佳 K16 被 Residual 选中|Residual 为空|每个 Q16 的 Residual K16 数|
|---|---:|---:|---:|---:|
|全部 3,456 个 Q16|0.90|21.3%|59.6%|均值 157.3，中位数 0|
|1,728 个高误差 Q16|0.90|32.5%|40.1%|均值 271.8，中位数 83|
|173 个严重遗漏|0.90|**3.5%**|**74.6%**|均值 35.9，中位数 0|
|173 个严重遗漏|0.95|16.2%|50.3%|均值 158.1，中位数 0|

这个结果揭示了当前规则最致命的失配：**越是存在高收益遗漏的 Q16，proxy 越可能声称 Core 已经覆盖了足够质量，于是 Residual 直接为空。** 与此同时，其他 Q16 又会产生数百个 Residual tile。问题不是简单的“总预算太少”，而是预算投错了 query。

把 `p_total` 从 0.90 提高到 0.95 会令严重遗漏上的平均 tile 数从 35.9 增至 158.1，但真实最佳块召回仍只有 16.2%。因此继续提高 Top-p 会先显著增加成本，不能根治排序错误。

这项结论严格对应数据生成时的 `topk_topp + total Top-p Residual`。当前推理入口的默认 route 已是 `fine_topk_occupancy`；没有该默认路径对应的逐 K16 add-back dump 时，不能把上述 3.5% 直接当作它的实测召回率。不过两条路径若继续依赖同一个 mean-pooled proxy，都会面对这里已经证明的 proxy 盲区。

## 5. 对方法设计的直接建议

### 5.1 应保留的部分

- 保留 Q16×K16 作为 Residual 最小选择单位；在单位成本相同时，它与“恢复性价比最高”目标一致。
- 保留独立 add-back 的 \(\Delta E\) 作为监督标签或 oracle 评价标签。
- 用 Layer/Head/step 先验做 **budget gating**：先决定哪些 query 值得运行更强的候选发现器。
- 把时间距离、proxy tile score、Macro \(A\)、Macro \(M\) 作为多个输入特征，而不是任一单独规则。

### 5.2 不应直接采用的部分

- 不应把 proxy Macro \(M\) 大直接等同于单 K16 恢复性价比高。
- 不应把全局固定 K anchor 作为主要补偿方案。
- 不应只补 Hilbert index 邻域或空间最近邻。
- 不应仅靠提高 total Top-p 来换召回；现有结果显示其成本增长远快于严重遗漏召回。

### 5.3 下一版 score 应瞄准什么

数据表明 dense attention mass 已经是非常强的 oracle：严重遗漏 Top5 候选召回为 83.2%。因此下一步最值得做的不是发明更多静态位置规则，而是研究为什么 16-token mean pooling 抹掉了该信号。候选方向应围绕“保留 tile 内峰值/离散度”展开，例如：

- Q/K token 范数和极值，而不只取 16-token 均值；
- tile 内若干代表 token 的最大 QK 或小样本 log-sum-exp；
- mean、max、variance/entropy 的组合；
- 时间距离软先验；
- 仅在高风险 Layer/Head 上使用更昂贵的细粒度 proxy。

评价时应固定计算预算，报告候选级 Top1/Top5/Top20 recall，并同时报告：

\[
\text{Recovered-DeltaE@k}
=\frac{\max_{j\in\mathrm{Top}k}\Delta E_j}
{\max_{j\in\mathrm{all\ omitted}}\Delta E_j}.
\]

只报告候选召回仍不够，因为未命中 oracle-best 的候选也可能恢复几乎相同的误差；`Recovered-DeltaE@k` 更直接对应最终质量/成本。

## 最终判断

现有数据已经能够清楚回答“Core 大块选完后哪些小块值得补”的离线 ground truth，也已经排除了三个过于简单的答案：当前 proxy 的 Top-p、固定 K anchor、普通局部邻域。

真正可利用的稳定规律有两层：

1. **事件层面：** 严重遗漏集中在 Layer 12 的少数 heads，并偏向 Step 12/24；这可以决定把检测预算放在哪里。
2. **候选层面：** 高收益 K16 往往时间邻近、空间非局部；真实 dense mass 与恢复收益高度相关，但当前 mean-pooled proxy 没有保住这个信号。

所以，下一步方法的核心问题应表述为：**如何用远低于 dense attention 的代价，在高风险 query 上近似 tile-level dense mass/峰值，并在 Core 补集中排出少量 K16 候选。** 这比继续讨论 “\(M\) 大不大” 更接近真正的一阵见血。
